# lottery

A lottery / raffle contract using a commit-reveal scheme for randomness,
generated by [soroban-forge](https://github.com/soroban-forge-labs/soroban-forge)
from the `lottery` template.

## How it works

1. **Enter (commit phase)** — before `commit_deadline`, each entrant calls
   `enter` with `sha256(nonce)` for a secret nonce only they know.
2. **Reveal (reveal phase)** — between `commit_deadline` and
   `reveal_deadline`, entrants call `reveal` with their nonce; the contract
   checks it hashes to their commitment.
3. **Draw** — after `reveal_deadline`, anyone can call `draw`. The contract
   XORs every revealed nonce into a single seed and picks the winner from
   entrants who revealed. Entrants who never reveal forfeit — no single
   party controls the final seed alone.

## Develop

```sh
cargo test                 # run unit tests
stellar contract build     # build the deployable wasm
```

## Deploy to testnet

```sh
stellar contract deploy \
  --wasm target/wasm32v1-none/release/lottery.wasm \
  --source-account <your-identity> \
  --network testnet
```

Then initialize and enter:

```sh
stellar contract invoke \
  --id <CONTRACT_ID> \
  --source-account <ADMIN> \
  --network testnet \
  -- initialize \
  --admin <ADMIN_ADDRESS> \
  --commit_deadline 1735689600 \
  --reveal_deadline 1735693200

stellar contract invoke \
  --id <CONTRACT_ID> \
  --source-account <ENTRANT> \
  --network testnet \
  -- enter \
  --entrant <ENTRANT_ADDRESS> \
  --commitment <SHA256_OF_NONCE>
```

Reveal and draw:

```sh
stellar contract invoke \
  --id <CONTRACT_ID> \
  --source-account <ENTRANT> \
  --network testnet \
  -- reveal \
  --entrant <ENTRANT_ADDRESS> \
  --nonce <NONCE>

stellar contract invoke \
  --id <CONTRACT_ID> \
  --source-account <ANY_ACCOUNT> \
  --network testnet \
  -- draw
```

## Security & Limitations

### Last-revealer advantage

This template implements a plain commit-reveal scheme. It has an inherent limitation: **the last entrant to reveal can precompute the seed with and without their nonce**. If withholding their reveal yields a winning outcome for them (or an accomplice), they can simply choose not to reveal. Because entrants who do not reveal are excluded from the draw without penalty, the last revealer can steer or bias the outcome.

**When not to use this template:**
Do not use this plain commit-reveal template for production lotteries, high-value raffles, or games where participants have a financial incentive to withhold their reveal. For high-stakes applications on Stellar/Soroban, use a Verifiable Random Function (VRF) or an external oracle that provides unbiasable randomness.

See [security-considerations.md](https://github.com/soroban-forge-labs/soroban-forge/blob/main/docs/security-considerations.md) for what it does and does not protect against.
